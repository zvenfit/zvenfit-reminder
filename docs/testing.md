# Стратегия тестирования

Проект использует три уровня проверки. Постоянное отдельное облачное окружение
на текущем этапе не требуется: быстрые проверки полностью изолированы, а
интеграционные можно поднимать локально или одноразово в CI.

## 1. Unit и build — каждый коммит

`npm run check` проверяет миграции, типы, доменную логику, API и cron, а затем
собирает все production-пакеты. Эти тесты не обращаются в Telegram или облако.

## 2. Mini App E2E — каждый pull request и push в main

`npm run test:e2e` запускает Playwright в Chromium с мобильным и десктопным
профилями. Vite стартует автоматически, а Telegram WebApp и REST API подменяются
на границе браузера. Поэтому тесты воспроизводимы и не требуют секретов.

Проверяемые сценарии:

- изоляция данных при переключении групп;
- ограничения обычного участника и личное напоминание себе;
- отсрочка, выполнение и отмена выполнения;
- переназначение напоминания после ухода ответственного;
- редактирование, пауза, продолжение и завершение серии;
- сокрытие действий, недоступных обычному участнику;
- управление ролью организатора;
- изменение ритма группы и подтверждаемая передача владельца;
- предупреждение, если личный чат с ботом ещё не открыт;
- работоспособность встроенного preview-режима и сохранение созданного элемента.

Webhook unit tests additionally verify the secret-protected direct function
route and Telegram-native fallback replies for message and callback failures.

Артефакты падения — скриншот и Playwright trace — сохраняются в
`test-results/` и не коммитятся.

## 3. YDB integration — следующий слой

Локальная YDB поднимается через `npm run dev:stack`. Отдельный интеграционный
набор должен проверять реальные запросы репозиториев, транзакции, индексы,
изоляцию workspace и повторное применение миграций. Для этого нужен Docker;
пока слой не автоматизирован и остаётся известным пробелом.

## Telegram и production

У Telegram нет полноценного sandbox для группового бота. Интеграцию с ним
проверяем коротким smoke-тестом в отдельной тестовой группе после изменения
команд, callback-кнопок или отправки уведомлений. Production-секреты и реальная
YDB никогда не используются в Playwright-тестах.

После push в `main` production workflow дополнительно:

- применяет ещё не выполненные YDB-миграции и проверяет их checksums;
- разворачивает обе функции под runtime service account;
- публикует Mini App;
- устанавливает webhook и отправляет подписанный синтетический update через
  Cloudflare Worker;
- вызывает защищённый `/health/telegram` внутри новой версии bot-функции и
  проверяет реальный исходящий `getMe` к Telegram API;
- проверяет через `getWebhookInfo`, что URL и `allowed_updates` сохранены.

Этот автоматический smoke подтверждает инфраструктурный маршрут, но не заменяет
ручной сценарий в тестовой Telegram-группе: создание workspace, получение
уведомления, snooze, completion/undo и следующий recurrence.
